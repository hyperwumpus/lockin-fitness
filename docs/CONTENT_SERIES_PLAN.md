# Content Series Plan — “I Built a Real-Life System to Force Myself to Level Up”

## Series promise
A continuing transformation story where the audience can return knowing exactly what the next chapter is: build the System, obey the quests, show the consequences, improve the app from real-world failures, and level up from deconditioned/“skinny fat” to a lean, capable, calisthenics-focused athlete.

The software and the transformation are one story. The app is not a side project; it is the mechanism driving the transformation.

## Core narrative pillars
1. **Build the System** — designing/coding features because a real problem appeared.
2. **Obey the System** — workouts, food missions, wake missions and daily execution.
3. **Level Up** — weight trend, strength, calisthenics skills, conditioning and visual progress.
4. **Penalty Quests** — genuine precommitted consequences when required missions are ignored.
5. **Side Quests** — races, fitness challenges, public challenges, collaboration, climbing, martial-arts intro sessions, hiking, skill tests, etc.
6. **Boss Fights** — major benchmarks such as first pull-up, 30-day checkpoint, 10-lb loss, first 5K, first handstand, first competition.

## Launch arc — first 6 videos
### Episode 0 — Why I Need a System
Hook: “I have the gym, equipment, time and a plan. I still don’t do it. So I’m building something that makes quitting harder than doing the work.”
Show current starting point, the friction problem, 190-lb baseline, athletic/Genji-inspired goal, and rules for safe real-world consequences.

### Episode 1 — I Built V0.1
Show the prototype: quests, workout mode, meals, XP, penalty vault and content capture. Explain what is real today vs future phone-level features.

### Episode 2 — Day 1: The System Goes Live
Film morning decision point, training, meal execution, rest timer and first completion screen. Avoid pretending everything is cinematic; the ordinary execution is the proof.

### Episode 3 — The First Week Report
Use a repeatable scoreboard: workouts completed, protein adherence, weight trend, mission completion %, penalty count, current rank, one thing that failed, one app change being made.

### Episode 4 — First Penalty Quest (only when organically earned)
Do not manufacture a failure. If a mission is legitimately failed, show the consequence: safe physical penalty + Pokémon pack into the Penalty Vault + what the app changes to prevent the same failure.

### Episode 5 — System Update 0.2
Build the feature demanded by real behavior: stronger alarms, QR wake challenge, barcode food logging, native iPhone shell, etc.

## Repeatable weekly format
**Cold open:** the week’s biggest win/failure in 5–10 seconds.
**System Status:** weight trend, rank/XP, streak, workouts, skill progress.
**Main story:** one challenge, failure, breakthrough or build problem.
**App patch:** what changed in the System because of that week.
**Next quest:** one clear objective that gives viewers a reason to return.

## Content continuity device
Every piece should visibly use one of these labels:
- DAILY QUEST
- SYSTEM UPDATE
- PENALTY QUEST
- SIDE QUEST
- BOSS FIGHT
- LEVEL UP
- WEEKLY REPORT

This creates recognizable episodes without requiring every video to have the same format.

## Penalty Vault content rules
- Precommit which sealed packs/items are eligible before failure.
- Never change the rules after seeing the pack/item.
- If a pack is forfeited, the audience should understand exactly why.
- Options: give away sealed; open and give away the best pull; monthly vault giveaway; donate packs at a community event.
- Do not manufacture mission failures for views.

## Bucked Up / external challenge integration
If a Bucked Up Bootcamp or other legitimate fitness challenge is joined, treat it as a **limited-time Boss Fight arc**, not the identity of the whole series:
- “Boss Fight Accepted: [challenge]”
- record official starting measurements/rules
- weekly challenge-specific progress segment
- preserve LOCK//IN training/recovery rules unless the event requires otherwise
- disclose sponsorship/affiliate relationships if any
- verify current official rules, dates, eligibility and prize terms before announcing money/prizes

A future portfolio/career video can frame the project as: “I had a behavior problem, built a product to solve it, tested it publicly, gathered feedback, and iterated.”

## What to capture every day (low friction)
1. 3–5 sec System screen before mission.
2. One clip from the workout / side quest.
3. One meal or protein clip only if visually useful.
4. 5–15 sec post-mission reaction or voice memo.
5. Screenshot/stat if a milestone occurs.

Do not vlog the entire day. Capture evidence and story beats.
